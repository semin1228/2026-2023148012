# PRE_PRD: Sonic 애니메이션 뷰어 (LEC09)

## 1. 목표

`sonic-sprite.png` 에 들어 있는 소닉의 모든 동작을 pico2d 창에서 차례대로 재생하는 뷰어를 만든다.
한 번에 완성하지 않고, 작은 단계로 나눠 구현과 커밋을 반복하면서 만든다.

## 2. 핵심 조건

| 항목 | 조건 |
| --- | --- |
| 도구와 파일 | Python, pico2d, 단일 `sonic_animation_viewer.py`, `sonic-sprite.png` |
| 재생 | 이미지의 모든 동작을 원본 크기의 4배로 표시 |
| 전환 | 동작별 5회 반복, 1초 정지, 다음 동작으로 전환 |
| 전체 순환 | 마지막 동작 뒤 첫 동작부터 다시 재생 |
| 개발 과정 | 단계별 구현과 커밋을 반복해 최소 20회 커밋 |

## 3. 입력 자료: sonic-sprite.png

| 항목 | 내용 |
| --- | --- |
| 크기 | 399 x 525, RGBA |
| 배경 | 이미 투명(0, 0, 0, 0)이라 배경 제거 작업은 필요 없음 |
| 제외 영역 | 맨 위 제목 `Classic Sonic Sprites`(y 1~32), 맨 아래 크레딧과 다른 캐릭터(y 472~) |
| 프레임 배치 | 동작마다 한 줄. 프레임 폭·높이·간격이 일정하지 않음 |

### 동작 줄 (1차 분석)

픽셀 분석으로 구한 1차 결과다. y 는 이미지 위쪽 기준이고, pico2d `clip_draw` 의 bottom 은 `525 - 1 - (아래 y)` 로 바꿔야 한다.
프레임 수와 동작 이름은 **추정값**이므로 프레임 좌표를 확정하는 단계에서 다시 확인한다.

| 줄 | y 범위 | 높이 | 추정 프레임 수 | 추정 동작 | 메모 |
| --- | --- | --- | --- | --- | --- |
| 1 | 39~77 | 39 | 약 11 | 서기 / 대기 | 붙어 있는 프레임이 있어 분리 필요 |
| 2 | 79~117 | 39 | 12 | 걷기 → 달리기 | 1px 잡티 1개 제외 |
| 3 | 121~162 | 42 | 약 7 | 올려보기·웅크리기 등 | 붉은 잔상이 붙은 프레임 분리 필요 |
| 4 | 167~199 | 33 | 9 | 스핀 대시(회전) | |
| 5 | 206~232 | 27 | 6 | 구르기(공) | |
| 6 | 238~273 | 36 | 6 | 빠른 달리기 | |
| 7 | 283~316 | 34 | 6 | 8자 다리 달리기 | 뒤쪽 프레임 폭이 39px 로 넓음 |
| 8 | 326~369 | 44 | 8 | 뒤돌기·피격 등 | 한 줄에 여러 동작이 섞였을 수 있음 |
| 9 | 377~416 | 40 | 8 | 밀기·미끄러짐 등 | |
| 10 | 426~467 | 42 | 4 | 기타 | |

## 4. 재생 규칙 상세

| 항목 | 규칙 |
| --- | --- |
| 확대 | 모든 프레임을 원본의 4배로 그린다. 가장 큰 프레임(약 44px 높이)도 176px 이라 화면 안에 들어간다 |
| 위치 | 캐릭터를 화면 가운데에 그린다. 프레임 크기가 달라도 발이 같은 바닥선에 오도록 맞춘다 |
| 프레임 시간 | 기본 0.1초. 동작별로 다르게 할지는 구현 중에 정한다 |
| 1회 반복 | 그 동작의 첫 프레임부터 마지막 프레임까지 한 번 보여 주는 것 |
| 5회 반복 후 | 마지막 프레임을 1초 동안 멈춘 채 보여 준다 |
| 전환 | 1초 정지가 끝나면 다음 동작의 첫 프레임부터 시작한다 |
| 순환 | 마지막 동작이 끝나면 첫 동작으로 돌아간다. 창을 닫을 때까지 계속 |
| 종료 | 창 닫기(SDL_QUIT) 또는 ESC |

## 5. 화면 구성

- 캔버스 800 x 600
- 단색 배경 위에 캐릭터 1개
- 화면 위쪽에 현재 동작 이름, 반복 횟수(예: `RUN 3/5`)를 글자로 표시 (선택)

## 6. 범위 밖

- 키보드로 동작 고르기, 속도 조절 등 조작 기능 (필수 조건을 다 끝낸 뒤 여유가 있으면 추가)
- 사운드
- 시트 밖 이미지 사용

## 7. 개발 단계와 커밋 계획

각 단계는 **구현 → 실행 확인 → 커밋** 으로 끝낸다. 한 커밋에는 한 가지 변경만 담고, 무엇을 왜 바꿨는지 메시지에 남긴다.

| # | 단계 | 커밋 메시지 예 |
| --- | --- | --- |
| 1 | PRE_PRD 작성 | LEC09: 애니메이션 뷰어 사전 요구사항(PRE_PRD) 작성 |
| 2 | 빈 게임 루프 | LEC09: 캔버스를 열고 닫는 기본 게임 루프 작성 |
| 3 | 종료 처리 | LEC09: 창 닫기와 ESC 로 종료하도록 이벤트 처리 |
| 4 | 시트 불러오기 | LEC09: sonic-sprite.png 를 불러와 원본 크기로 표시 |
| 5 | 프레임 1개 자르기 | LEC09: clip_draw 로 첫 프레임만 잘라 그리기 |
| 6 | 4배 확대 | LEC09: 프레임을 원본의 4배로 확대해 그리기 |
| 7 | 첫 동작 재생 | LEC09: 첫 동작(대기)의 프레임을 차례로 넘겨 재생 |
| 8 | 시간 기반 재생 | LEC09: 프레임 전환을 루프 횟수 대신 경과 시간 기준으로 변경 |
| 9 | 동작 표 구조 | LEC09: 동작별 프레임 좌표를 표(리스트)로 분리 |
| 10 | 바닥 정렬 | LEC09: 프레임 높이가 달라도 발이 같은 바닥선에 오도록 정렬 |
| 11 | 5회 반복 | LEC09: 동작마다 5회 반복 후 다음 동작으로 넘어가기 |
| 12 | 1초 정지 | LEC09: 5회 반복 뒤 마지막 프레임에서 1초 정지 |
| 13 | 전체 순환 | LEC09: 마지막 동작 뒤 첫 동작으로 돌아가도록 순환 |
| 14~19 | 동작 추가 (줄 2~10) | LEC09: ○○ 동작 프레임 좌표 추가 (한두 동작씩 나눠 커밋) |
| 20 | 프레임 좌표 검수 | LEC09: 붙어 있던 프레임 분리, 잘린 프레임 좌표 수정 |
| 21 | 정보 표시 | LEC09: 화면 위쪽에 동작 이름과 반복 횟수 표시 |
| 22 | 상수 정리 | LEC09: 반복 횟수, 정지 시간, 배율을 상수로 정리 |
| 23 | 설명 주석 | LEC09: 맨 위 설명 주석에 동작 목록과 재생 규칙 반영 |

14~19 를 나누면 전체 23회 이상이 되어 최소 20회 조건을 넘는다.

## 8. 검증 방법

| 항목 | 확인 방법 |
| --- | --- |
| 모든 동작 | 시트의 동작 줄(1~10)이 모두 화면에 한 번씩 나오는지 본다 |
| 4배 확대 | 화면에 그려진 크기가 원본 프레임 크기 x 4 인지 확인한다 |
| 5회 반복 | 화면의 반복 횟수 표시 또는 출력(print)으로 1~5 를 센다 |
| 1초 정지 | 정지 시작·끝 시각을 출력해 약 1초인지 확인한다 |
| 순환 | 마지막 동작 뒤에 첫 동작이 다시 나오는지 본다 |
| 프레임 잘림 | 이웃 프레임이 섞여 보이거나 몸이 잘리지 않는지 본다 |
| 커밋 수 | `git log --oneline` 으로 20회 이상인지 센다 |

## 9. 미결 사항

- 줄 1, 3 의 붙어 있는 프레임을 어디서 나눌지
- 줄 8, 9 처럼 여러 동작이 섞인 줄을 한 동작으로 볼지, 나눠서 볼지
- 동작별 프레임 시간을 같게 할지, 동작 느낌에 맞춰 다르게 할지
- 몸통 위치(가로)도 정렬할지, 프레임 가운데에 맞추는 것으로 충분한지
